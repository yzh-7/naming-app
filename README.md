# 取名（典籍取词）

一个离线运行的取名辅助工具。它从七部中文典籍中按固定口径取出词语，组合成单字名与双字名，并为每个结果附上出处原句、读音、字义、笔画与用字频次等信息。

在线版本：<https://yzh-7.github.io/naming-app/>

语料在构建期固化为 JSON 随包发布，页面运行时不发起任何网络请求，筛选与计算全部在浏览器内完成。站点可安装为 PWA，断网可用。

## 概述

取词口径（Pool-B）：

1. 典籍原文按 `。！？；` 分句、按 `，、：` 分句读，去标点。
2. 第一个字落在音步起点（**严格诗体的书**按句长 4／5／7 定起点；《论语》《道德经》与词那一本不按诗体取，起点取句内全部位置——这三本共贡献 966／1,660 条，所以对过半候选「依诗体定起点」是描述而不是判据），第二个字在同一句读内、与首字间隔不超过 3 字。
3. 两个字都必须在名用字白名单内；虚词、忌讳字、现代高频成词与噪声词被剔除。

七部典籍及其规模：

| 典籍 | 篇数 | 取词段数 | 取词段字符数 |
|---|---:|---:|---:|
| 诗经 | 305 | 7,260 | 29,250 |
| 楚辞 | 65 | 5,495 | 24,588 |
| 论语 | 20 | 3,682 | 15,720 |
| 水墨唐诗 | 176 | 991 | 5,832 |
| 宋词三百首 | 280 | 5,208 | 23,960 |
| 道法 | 22 行 | 68 | 321 |
| 乐府诗集 | 20 篇 | 429 | 2,134 |
| 合计 | — | 23,133 | 101,805 |

经上述口径得到的候选池：双名 1,660 条（间隔 1 / 2 / 3 字分别为 803 / 506 / 351）、单字名 234 个、名用字白名单 310 字（种子 268 ＋ 人工过字保留 42）、出处今译进包 2,207 句——共享原句表里每一句都有译文了。

另有**第二个来源**——真实人名档 5,096 个双字名，来自 120 万条真实姓名语料（入选次数 10～600，口径见 `DESIGN.md` 1.7）：它的证据是「真有人这么叫过 N 次」，不是典籍出处，卡片与导出都单独标注，可用「来源」筛选单独看或排除。默认界面（成词门槛开着）给的是典籍成词层 525 条 ＋ 真实人名 5,096 条 ＝ 5,621 条。

这 1,660 条不是全都摆到用户面前：界面默认只给「成词层」525 条——这两个字在七部典籍正文里挨着出现过两次以上（274 条），或现代汉语词表收录了这个词（381 条），或是典籍里的叠字（48 条）。其余 1,135 条是从同一句读里各取一字拼出来的（其中 659 条还把原句里本来挨着的那对字剪开了），要看得把它们点开来：卡片上的「成词依据」标签与分数明细把每一条的证据写清楚。分数明细里另有一行「原句属名句层：这个词在典籍正文里反复出现」＋8 分：判据是跨全池的单一阈值——候选全池里有相邻复现（≥1 次）的那 826 条取词，其复现次数数列的 90 分位＝4 次，达到就带这一分（当前 93 条双名 ＋ 64 条单字名；明月 31 次、君子 296 次都在里面）。阈值与每一条判定由 `npm run verify` 从 `data/raw` 独立重算核对，口径见 `docs/user-guide/03-名字是怎么来的.md`。

## 环境要求

- Node.js 22.19 或更高版本。版本约束见 `package.json` 的 `engines` 与 `.nvmrc`，CI 覆盖 22 与 24。
- 端到端测试与设计体检需要 Chromium，首次执行 `npx playwright install chromium`。
- 浏览器：支持现代 ES 模块与 CSS 自定义属性的版本。

## 快速开始

```bash
$ npm install
$ npm run dev
```

`dev` 会先生成数据再启动开发服务器。构建产物位于 `dist/`，本地预览用 `vite preview` 或 `npm run serve`。

## 功能

### 生成

姓、搜索、篇名、指定字、禁用字这几处**打繁体也认**（0.20.0）：输入框保留你打下的字形，匹配按简体去，控件下面给一行「按简体匹配：蘇 → 苏」。输入姓氏（支持复姓，多音姓可选择读音），输出一页候选。每页可换一批，分页不重复、不漏项。每张卡片包含：读音与声调、出处原句与今译、字义、笔画与字形结构、每个字的用字常见度、多音字提示、小名建议，以及收藏、拉黑、分享、复制四个动作。

### 自选

自行选择姓氏与一到两个字，可选任意汉字；不在名用字白名单内的字会标注出来。自选页只做读音、谐音与字形核对，不套用候选池的分数。有典籍出处的组合显示原句与今译，没有出处的组合显示「未见此搭配」，且不提供收藏入口。支持随机组合（默认只在有出处的搭配中随机）与「同句读搭配字」查询。草稿保存在本机。

### 筛选

性别风格（偏男／中性／偏女三档互斥）、只看成词的名字（默认开）、字数（单名／双名）、典籍开关、只看叠字（典籍侧的叠字加真实人名档里写法本就是叠字的名字）、关键词搜索、排序（分数／笔画／常见度／典籍）、指定用字及其位置、禁用字（避讳字）、整名笔画上限、避开两字同结构、逐字用字常见度下限、来源（全部／只看典籍／只看真实人名）。卡片上另有两类证据标签：成词依据（这两个字在典籍里挨不挨着）与「真名 · N 人用过」（这名字在 120 万条真实姓名语料里真有人叫过多少次，没记录的不挂标签、也不扣分）。

禁用字用于长辈名讳、家里忌讳的字：名里出现其中任意一个，这条候选整条不出现；只查名，不查姓（姓是用户自己的姓）。最多 8 个字，重复字不重复计，非汉字不进状态。它与指定用字是交集：同一个字既指定又禁用时结果为 0，页面直说没有候选，不硬凑。自选页是你自己挑字，不受禁用字筛除，但挑到禁用字时会明说。

### 收藏与拉黑

收藏支持备注、分组、分组过滤、搜索与排序。勾选 2–3 个收藏可进入对比表。拉黑名单记录需要排除的名字，并参与生成结果过滤。收藏与拉黑存在本机 `localStorage`。

### 导入、导出与链接

- 导出收藏、拉黑与筛选配置为 JSON；导入时可选择合并或覆盖，导入文件会先校验。超过 8 MiB 的文件直接拒绝并说明上限，不读进内存（本应用自己导出的一份最大的——全量候选——约 0.6 MiB）。
- 导出当前筛选命中的全部候选为 JSON 或 CSV（含出处原句与今译），不限于当前页。CSV 单元格以 `=`、`+`、`-`、`@` 打头时前置一个前导单引号，避免被 Excel／WPS 当成公式执行。
- 复制当前页面的链接。URL 只编码筛选条件（姓氏、读音、性别档 `g`、成词门槛 `wd`、字数、搜索词、排序、笔画上限、常见度下限、典籍开关、禁用字 `ac` 等），不包含收藏与拉黑。链接里出现某一项，这一项就进入状态；取值不可信时回默认值，不夹到边界，也不静默丢弃。链接没有出现的项沿用本机已存的偏好。

### 分享与打印

单个名字的分享卡片图片（含原句、今译与本地生成的二维码）、收藏名单长图、打印名单。打印样式只保留卡片正文，动作区与折叠详情不打印。

### 主题

跟随系统、浅色、深色三档，保存在本机键 `naming.theme.v1`，标记加在 `<html>` 上。选择「跟随系统」时随系统偏好实时切换。四个页面以及分享卡、对比表、导入弹窗均有对应的深色配色。

### 响应式与可访问性

- 320px 宽度起无横向溢出。
- 视口宽度小于 1024px 时交互目标高度不小于 44px，平板宽度（768px）同样按触摸尺寸计算。
- 断点：`xs` 384、`sm` 640、`lg` 1024、`xl` 1280。
- 页头固定（sticky），切换页面时滚动位置回到顶部。
- 状态按钮使用 `aria-pressed`，折叠区使用 `details/summary`，装饰字符标记 `aria-hidden`。
- 界面文案无衬线，名字用衬线大字，数字使用 `tabular-nums`，正文行长上限约 40 字。
- 键盘第一站是「跳到内容」（0.18.0 起它被端到端钉住）：平时 `sr-only`，Tab 到它就现身；`main` 带 `tabIndex={-1}`，回车之后焦点真的落到正文上，屏幕阅读器接着往下读。
- 破坏性操作给撤销：收藏、拉黑、分组改名与解散、导入确认之后，底部那条反馈里多一枚「撤销「…」」按钮。它只认「这一步之后没再动过收藏与名单」——动过就明说「撤销失效」，绝不拿旧快照覆盖后来的改动。
- Windows 高对比（强制颜色）模式有一套 `@media (forced-colors: active)` 规则：取词高亮改成加粗＋下划线，选中态改成 2px 边框＋字重，凡是原来只靠颜色分辨的地方都补一层不靠颜色的表达。

### 对外元信息（0.19.0）

页面是自己的一份说明书，抓取器与安装流程都读它：

- `<link rel="canonical">` 指向 `https://yzh-7.github.io/naming-app/`，与 `og:url` 同址（端到端钉住两处必须同值，否则抓取器会把其中一个当重复页）。
- `public/robots.txt` 放行收录并指向 `public/sitemap.xml`；sitemap 里只有这一个地址（各页签是 hash，不算不同页面），**不写 `lastmod`**——那是发布时刻的派生值，本项目的版本口径由 `package.json` 与标签说话，不在第二处重复一份会漂移的事实。
- `<noscript>` 写在服务器返回的 HTML 里（不是 JS 插进去的）：关掉脚本的人能看到一句人话——这站的计算都在本机、需要浏览器允许执行 JavaScript，以及去哪儿拿双击即用的单文件版。
- manifest 补了 `id`（缺它时安装出来的应用与网页算两个身份）与 `categories`，并把 `theme_color` 从强调色 `#9a3a12` 改成页面底色 `#f6f5f1`：manifest 只有一个主题色，用在安装期与闪屏，运行中的深浅切换由页面里两条按 `prefers-color-scheme` 分档的 `theme-color` meta 负责，两处原来不一致会让安装那一下闪一个和界面无关的颜色。
- **`screenshots` 没加**，实测过代价：现截一张 390×844 的 JPEG（质量 50）是 24,309 B，质量 60 是 26,996 B；540×1170 质量 55 是 42,499 B，同一张 PNG 是 96,204 B（gzip 后）。而站点那条体积预算的余量现在是 21,049 B（0.20.0 带表之后），扣掉 CI 压缩器口径差约 1,900 B 之后约 19.1 KB——一张最小可用的截图会把它吃光还多。要装这张图就得先放宽上限，那是需要用户当场决定的事，不在这次顺手做掉。

### PWA

`public/manifest.webmanifest` 与 Service Worker 支持安装与离线访问。有新版本或处于离线状态时，页面顶部给出提示。应用版本只有一个来源（`package.json`），页脚、页面 meta 与 Service Worker 注册参数三处出口都由它注入；离线缓存名按当前构建产物算出，不手工维护。口径见 `DESIGN.md`「版本与缓存」。

## 数据来源与许可

本仓库自己写的代码与文档按 MIT 许可，全文见 [LICENSE](LICENSE)。`data/raw/` 下的上游语料、字表与派生输入按各自上游许可，本仓库不重新授权它们；构建期用到的第三方库同样按上游许可，两者都不在 MIT 范围内。

原始语料、字表与派生输入位于 `data/raw/`，逐项上游、许可与用途见 [data/raw/LICENSES.md](data/raw/LICENSES.md)，许可全文副本位于 `data/raw/licenses/`。`data/raw/SHA256SUMS` 记录输入指纹，`npm run verify` 在构建期校验；改动原始数据必须同步更新指纹。

构建产物位于 `src/data/`，由 `scripts/build-data.mjs` 生成，不要手工编辑。出处今译（`data/raw/line_gloss.tsv`）由本项目撰写，只解释句意。

## 构建与体积预算

`vite.config.ts` 用 `manualChunks` 把产物分成三块：`vendor`（React 等依赖）、`data`（固化的词典与候选 JSON）、`index`（业务代码）。数据块只打包、不发起请求，单独分块便于长期缓存。

体积门禁由 `scripts/size-check.mjs` 执行，两条判定都按 gzip 计，也都进退出码：非 HTML 资源合计不超过 448 KiB（0.16.0 起；此前是 400 KiB）；HTML 自身按产物形态取预算——站点版量的是页面壳（400 KiB，没放宽过），单文件版量的是整个产物（512 KiB；此前是 450 KiB），同时打印原文件大小与所用的压缩实现。当前实测（gzip level 9，版本 0.17.0，本机 zlib 1.3.1 口径；CI 的 zlib-ng 口径见该版 CI run 的体积门禁输出）：

| 产物 | 原文件 | gzip（CI 口径） | gzip（本机口径） | 预算 |
|---|---:|---:|---:|---:|
| 站点 `dist/` 非 HTML 资源合计 | — | 待该版 CI 记录 | 440,093 B（430.0 KiB） | 458,752 B |
| 站点 `dist/index.html` 页面壳 | 3,718 B | 待该版 CI 记录 | 1,745 B | 409,600 B |
| 单文件 `dist-single/index.html` | 1,673,038 B（1.60 MiB） | 待该版 CI 记录 | 463,802 B（452.9 KiB） | 524,288 B |

gzip 的结果与压缩实现有关：CI 的官方 Node 自带 zlib-ng，0.3.1 那轮同一份单文件产物压出 414,892 B，比本机系统 zlib 的 409,115 B 多 5,777 B（1.4%）；近几版（0.14.0 起）按同一份产物实测的口径差约 +1,900 B。同一份产物在两种实现下都必须过门禁，所以取较大的一侧作准；单文件产物把本体与数据全部装在 HTML 里，400 KiB 这条首屏预算对它过窄，单列为 450 KiB。

两条判定各自的余量按本机口径：站点 458,752 − 440,093 = 18,659 B（4.1%），单文件 524,288 − 463,802 = 60,486 B（11.5%）。扣掉 CI 压缩器与本机的口径差（约 +1,900 B）后，站点那条仍剩约 16.8 KB。**0.21.0 的净增是 437,703 → 440,093 B gzip，+2,390 B**：214 行照抄的今译改成白话直译，译文合计多 1,861 字（产物 `line_gloss.json` 112,742 → 118,337 B 原文件）。上一版 0.20.0 的净增是 432,182 → 437,703 B（+5,521 B），其中繁简对照表本身 4,782 B gzip。两版都没有动上限，也不需要动——0.19.0 先量代价再动手，买的就是这个判断（口径见 `DESIGN.md`「预研与实装：繁简输入归一花了多少体积」）。页面壳那一行每次构建会在 1～4 B 之间浮动（HTML 里有构建期生成的哈希），不作为口径变化的依据。
   **这两条上限是 0.16.0 放宽的，放宽的理由是产品决定不是技术妥协**：用户要求先把 web 端体验做好，不再拿旧安卓机与 PWA 的首屏下载量当硬约束，于是站点那条从 400 KiB（409,600 B）改到 448 KiB（458,752 B）、单文件那条从 450 KiB（460,800 B）改到 512 KiB（524,288 B），页面壳那条没动（400 KiB）。放宽之前的事实要留在这里：0.15.0 时站点余量只剩 3,371 B，补那 986 句今译（实测 24,907 B gzip）装不下，所以放宽发生在补译文之前，是这一版的第一个决定。放宽之后仍然按同一套门禁跑，脚本 `scripts/size-check.mjs` 里新旧两个数都写在了注释上。0.4.0 比 0.3.1 用掉 5,806 ## 部署

推送到 `main` 分支后由 GitHub Actions 构建并发布到 GitHub Pages。每个已发布版本对应一个注释标签；标签锚点规则、各版的提交锚点与升版本的条件见 `CHANGELOG.md` 开头的「版本索引」与「版本策略」。

| 工作流 | 文件 | 步骤 |
|---|---|---|
| CI | `.github/workflows/ci.yml` | 四个 job：构建矩阵（Node 22 与 24，含单文件版构建与体积检查）、端到端与 axe 扫描（Chromium＋Firefox）、设计体检、WebKit 哨兵档。依赖漏洞审计 `npm audit --audit-level=high` 只拦 high 与 critical。同一分支的并发运行只保留最新一次，单个 job 20 分钟超时，工作流权限只给 `contents: read` |
| 发布 | `.github/workflows/deploy-pages.yml` | 构建并上传 Pages 产物；单个 job 20 分钟超时 |
| 依赖更新 | `.github/dependabot.yml` | 每周六 09:00（Asia/Shanghai）开 PR：npm 只提 minor 与 patch（major 留给人工决定），标题前缀 `fix(deps)`，开放 PR 上限 5；GitHub Actions 依赖前缀 `chore(ci)` |

首次配置：

1. 创建公开仓库并推送代码。
2. 在仓库 Settings → Pages → Build and deployment 中，将 Source 设为 GitHub Actions。
3. 推送后访问 `https://<用户名>.github.io/naming-app/`。

免费账户只能从公开仓库发布 Pages。本项目不含密钥与个人数据。

## 适用范围与已知限制

- 应用提供的是可核对的信息：典籍出处、原句位置、字义、笔画与结构、读音与谐音、多音字、真实用名频次。不包含五行、八字、五格、生肖宜忌、吉凶或「补缺」建议。
- 卡片上的「部首」是《康熙字典》部首归属，只覆盖木、火、水、金、土五部中查得到的字（66 字；1,660 条双名中有 597 条至少一个字可标注）。未标注不代表该字没有五行属性。
- 卡片分数由本项目自定义规则计算（音韵、谐音、字频、字形、性别风格），只用于候选池内排序，不构成对名字优劣的评价。
- 界面上的带调拼音（如「松 sōng」）不是存下来的：产物里只存不带调音节与声调号，带调写法由 `src/engine/tone.ts` 按标调规则推导（有 a 标 a、`ou` 标 o、`iu` 标 u、`ui` 标 i，自成音节 m n ng ê 逐条列出）。9,629 条读音逐条与上游比对，任一条对不上就在 `src/engine/tone.test.ts` 判红；白名单成员同理由 `whitelist-L0.json` 推导。两处合计还回 20,386 B gzip。
