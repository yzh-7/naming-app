# 取名（典籍取词）

一个离线运行的取名辅助工具。它从七部中文典籍中按固定口径取出词语，组合成单字名与双字名，并为每个结果附上出处原句、读音、字义、笔画与用字频次等信息。

在线版本：<https://yzh-7.github.io/naming-app/>

语料在构建期固化为 JSON 随包发布，页面运行时不发起任何网络请求，筛选与计算全部在浏览器内完成。站点可安装为 PWA，断网可用。

## 概述

取词口径（Pool-B）：

1. 典籍原文按 `。！？；` 分句、按 `，、：` 分句读，去标点。
2. 第一个字落在音步起点（**严格诗体的书**按句长 4／5／7 定起点；《论语》《道德经》与词那一本不按诗体取，起点取句内全部位置——这三本共贡献 966／1,660 条，所以对过半候选「依诗体定起点」是描述而不是判据），第二个字在同一句读内、与首字间隔不超过 3 字。
3. 两个字都必须在名用字白名单内；虚词、忌讳字、现代高频成词与噪声词被剔除。

七部典籍及其规模：

| 典籍 | 篇数 | 取词段数 | 取词段字符数 |
|---|---:|---:|---:|
| 诗经 | 305 | 7,260 | 29,250 |
| 楚辞 | 65 | 5,495 | 24,588 |
| 论语 | 20 | 3,682 | 15,720 |
| 水墨唐诗 | 176 | 991 | 5,832 |
| 宋词三百首 | 280 | 5,208 | 23,960 |
| 道法 | 22 行 | 68 | 321 |
| 乐府诗集 | 20 篇 | 429 | 2,134 |
| 合计 | — | 23,133 | 101,805 |

经上述口径得到的候选池：双名 1,660 条（间隔 1 / 2 / 3 字分别为 803 / 506 / 351）、单字名 234 个、名用字白名单 310 字（种子 268 ＋ 人工过字保留 42）、出处今译进包 1,140 句。

另有**第二个来源**——真实人名档 5,096 个双字名，来自 120 万条真实姓名语料（入选次数 10～600，口径见 `DESIGN.md` 1.7）：它的证据是「真有人这么叫过 N 次」，不是典籍出处，卡片与导出都单独标注，可用「来源」筛选单独看或排除。默认界面（成词门槛开着）给的是典籍成词层 525 条 ＋ 真实人名 5,096 条 ＝ 5,621 条。

这 1,660 条不是全都摆到用户面前：界面默认只给「成词层」525 条——这两个字在七部典籍正文里挨着出现过两次以上（274 条），或现代汉语词表收录了这个词（381 条），或是典籍里的叠字（48 条）。其余 1,135 条是从同一句读里各取一字拼出来的（其中 659 条还把原句里本来挨着的那对字剪开了），要看得把它们点开来：卡片上的「成词依据」标签与分数明细把每一条的证据写清楚。

## 环境要求

- Node.js 22.19 或更高版本。版本约束见 `package.json` 的 `engines` 与 `.nvmrc`，CI 覆盖 22 与 24。
- 端到端测试与设计体检需要 Chromium，首次执行 `npx playwright install chromium`。
- 浏览器：支持现代 ES 模块与 CSS 自定义属性的版本。

## 功能

### 生成

输入姓氏（支持复姓，多音姓可选择读音），输出一页候选。每页可换一批，分页不重复、不漏项。每张卡片包含：读音与声调、出处原句与今译、字义、笔画与字形结构、每个字的用字常见度、多音字提示、小名建议，以及收藏、拉黑、分享、复制四个动作。

### 自选

自行选择姓氏与一到两个字，可选任意汉字；不在名用字白名单内的字会标注出来。自选页只做读音、谐音与字形核对，不套用候选池的分数。有典籍出处的组合显示原句与今译，没有出处的组合显示「未见此搭配」，且不提供收藏入口。支持随机组合（默认只在有出处的搭配中随机）与「同句读搭配字」查询。草稿保存在本机。

### 筛选

性别风格（偏男／中性／偏女三档互斥）、只看成词的名字（默认开）、字数（单名／双名）、典籍开关、只看叠字、关键词搜索、排序（分数／笔画／常见度／典籍）、指定用字及其位置、禁用字（避讳字）、整名笔画上限、避开两字同结构、逐字用字常见度下限、来源（全部／只看典籍／只看真实人名）。卡片上另有两类证据标签：成词依据（这两个字在典籍里挨不挨着）与「真名 · N 人用过」（这名字在 120 万条真实姓名语料里真有人叫过多少次，没记录的不挂标签、也不扣分）。

禁用字用于长辈名讳、家里忌讳的字：名里出现其中任意一个，这条候选整条不出现；只查名，不查姓（姓是用户自己的姓）。最多 8 个字，重复字不重复计，非汉字不进状态。它与指定用字是交集：同一个字既指定又禁用时结果为 0，页面直说没有候选，不硬凑。自选页是你自己挑字，不受禁用字筛除，但挑到禁用字时会明说。

### 收藏与拉黑

收藏支持备注、分组、分组过滤、搜索与排序。勾选 2–3 个收藏可进入对比表。拉黑名单记录需要排除的名字，并参与生成结果过滤。收藏与拉黑存在本机 `localStorage`。

### 导入、导出与链接

- 导出收藏、拉黑与筛选配置为 JSON；导入时可选择合并或覆盖，导入文件会先校验。超过 8 MiB 的文件直接拒绝并说明上限，不读进内存（本应用自己导出的一份最大的——全量候选——约 0.6 MiB）。
- 导出当前筛选命中的全部候选为 JSON 或 CSV（含出处原句与今译），不限于当前页。CSV 单元格以 `=`、`+`、`-`、`@` 打头时前置一个前导单引号，避免被 Excel／WPS 当成公式执行。
- 复制当前页面的链接。URL 只编码筛选条件（姓氏、读音、性别档 `g`、成词门槛 `wd`、字数、搜索词、排序、笔画上限、常见度下限、典籍开关、禁用字 `ac` 等），不包含收藏与拉黑。链接里出现某一项，这一项就进入状态；取值不可信时回默认值，不夹到边界，也不静默丢弃。链接没有出现的项沿用本机已存的偏好。

### 分享与打印

单个名字的分享卡片图片（含原句、今译与本地生成的二维码）、收藏名单长图、打印名单。打印样式只保留卡片正文，动作区与折叠详情不打印。

### 主题

跟随系统、浅色、深色三档，保存在本机键 `naming.theme.v1`，标记加在 `<html>` 上。选择「跟随系统」时随系统偏好实时切换。四个页面以及分享卡、对比表、导入弹窗均有对应的深色配色。

### 响应式与可访问性

- 320px 宽度起无横向溢出。
- 视口宽度小于 1024px 时交互目标高度不小于 44px，平板宽度（768px）同样按触摸尺寸计算。
- 断点：`xs` 384、`sm` 640、`lg` 1024、`xl` 1280。
- 页头固定（sticky），切换页面时滚动位置回到顶部。
- 状态按钮使用 `aria-pressed`，折叠区使用 `details/summary`，装饰字符标记 `aria-hidden`。
- 界面文案无衬线，名字用衬线大字，数字使用 `tabular-nums`，正文行长上限约 40 字。

### PWA

`public/manifest.webmanifest` 与 Service Worker 支持安装与离线访问。有新版本或处于离线状态时，页面顶部给出提示。应用版本只有一个来源（`package.json`），页脚、页面 meta 与 Service Worker 注册参数三处出口都由它注入；离线缓存名按当前构建产物算出，不手工维护。口径见 `DESIGN.md`「版本与缓存」。

## 构建与体积预算

`vite.config.ts` 用 `manualChunks` 把产物分成三块：`vendor`（React 等依赖）、`data`（固化的词典与候选 JSON）、`index`（业务代码）。数据块只打包、不发起请求，单独分块便于长期缓存。

体积门禁由 `scripts/size-check.mjs` 执行，两条判定都按 gzip 计，也都进退出码：非 HTML 资源合计不超过 400 KiB；HTML 自身按产物形态取预算——站点版量的是页面壳（400 KiB），单文件版量的是整个产物（450 KiB），同时打印原文件大小与所用的压缩实现。当前实测（gzip level 9，版本 0.12.0，本机 zlib 1.3.1 口径；CI 的 zlib-ng 口径见该版 CI run 的体积门禁输出）：

| 产物 | 原文件 | gzip（CI 口径） | gzip（本机口径） | 预算 |
|---|---:|---:|---:|---:|
| 站点 `dist/` 非 HTML 资源合计 | — | 待该版 CI 记录 | 373,056 B（364.3 KiB） | 409,600 B |
| 站点 `dist/index.html` 页面壳 | 2,922 B | 待该版 CI 记录 | 1,300 B | 409,600 B |
| 单文件 `dist-single/index.html` | 1,583,964 B（1.51 MiB） | 待该版 CI 记录 | 391,775 B（382.6 KiB） | 460,800 B |

gzip 的结果与压缩实现有关：CI 的官方 Node 自带 zlib-ng，同一份单文件产物压出 414,892 B，比本机系统 zlib 的 409,115 B 多 5,777 B（1.4%）。同一份产物在两种实现下都必须过门禁，所以取较大的一侧作准；单文件产物把本体与数据全部装在 HTML 里，400 KiB 这条首屏预算对它过窄，单列为 450 KiB。

两条判定各自的余量不同，先撞线的不是单文件那条。按本机口径，站点那条的余量是 409,600 − 373,056 = 36,544 B（8.9%），单文件那条是 460,800 − 391,775 = 69,025 B（15.0%）；语料增量同时加在两侧产物上，所以限制来自余量小的那条。0.4.0 比 0.3.1 用掉 5,806 B（成词证据的三个字段与卡片标签），随后把产物里冗余的 `chars` 字段去掉，还回 7,854 B（双名条目的 `chars` 恒等于 `name` 拆字，1,525 条存下来实测多花 7,951 B gzip，见 `DESIGN.md` 1.3.1），0.5.0 的真实用名两个字段用掉 3,196 B；0.6.0 的真实人名档用掉 9,244 B（1,362 条精简记录 7,904 B ＋ 界面与引擎约 1.3 KB）；0.7.0 的扩表用掉 8,364 B——135 条新双名按 73 B 一条算就是 10 KB 量级，扩表幅度最后是被这条预算砍下来的：按解锁量本可以放 385 条进来，最后把解锁最多的 岸 洲 汀 竹 书 陆 笔 弦 晏 琰 扶 涯 峦 澈 砚 与 离 行 长 怀 那批退回剔除才进得来。0.8.0 做掉的是编码那一头：带调拼音与白名单成员不再随包发（由引擎推导），还回 20,386 B gzip——站点余量从 3,689 B 回到 24,075 B，够放约 328 条完整记录的双名或约 1,380 条精简记录，**上限一条也没放宽**。`chars.json` 的 `pm` 字段单独占 22,604 B gzip。0.9.0 接着做同一族的候选池那一头：原句、篇名与作者集中成共享表 `sources.json`（1,221 条原句／545 篇，对应 1,660 条双名），取词段改存「起始下标＋长度」，`id` 不存整串而由「层＋书码＋篇名拼音＋名字拼音＋序号」重建，今译下标挂在原句表上——候选池 93,331 → 34,514 B gzip、单字名 15,888 → 5,068 B，两张表加进来 42,769 B，净省 27,654 B gzip。收藏、拉黑与分享链接里的 id 逐字不变（1,660 条双名与 234 条单字名逐字段比对，0 处不一致）。0.11.0 做的是功能审查的减法：`chars.json` 里的字表等级 `lvl` 删掉（8,105 份、运行时零读点，`chars.json` 90,620 → 85,836 B gzip），打分不再计算没人读的无声调拼音串与声母串，界面与存储删掉六处重复实现与四个走不到的分支，站点 377,255 → **372,981 B**（还回 4,274 B）。按边际成本换算有两条数，取决于砍掉的是哪 300 条，旧文档只写了大的那条：**0.9.0 共享表之后**用同一做法（从 `src/data/candidates.json` 删掉池子最后 300 条，重量全部数据文件的 gzip 差值）实测每条 **19.9 B** gzip——尾部那 300 条的原句与篇名大量与保留记录共享同一张 `sources.json`，砍掉它们连共享表也缩小；而 0.8.0 那套「每条自带原句与篇名」的产物形状下同一做法量出 72.4 B（CI 口径 73.3 B），那条数已经随编码失效，只留着当历史。按 19.9 B 算余量（36,544 B）能放约 1,800 条、按 72.4 B 算约 500 条，扩表幅度报这个区间，不再报单一数；若新增的名字只存名字与出处定位、不带今译与字义，实测每条 17.4 B gzip，同一份余量能装 1,200 条以上——这就是「名字不够多」这件事在体积上的实际边界。扩表前按站点那一行算幅度，新增典籍原文、字表与读音条目不在这 73.3 B 之内，只会让上限更早到。单文件那条不提预算（保持 450 KiB = 460,800 B）：要放宽的是一条永不发布的产物的天花板，真正的约束仍在站点那条，先放宽它只会让门禁允许语料长到线上发不出去的量。`dist-single/` 只用于体积核对，不发布。

## 部署

推送到 `main` 分支后由 GitHub Actions 构建并发布到 GitHub Pages。每个已发布版本对应一个注释标签；标签锚点规则、各版的提交锚点与升版本的条件见 `CHANGELOG.md` 开头的「版本索引」与「版本策略」。

| 工作流 | 文件 | 步骤 |
|---|---|---|
| CI | `.github/workflows/ci.yml` | 构建（Node 22 与 24）；单文件版构建与体积检查；依赖漏洞审计（`npm audit --audit-level=high`，只拦 high 与 critical）；端到端与 axe 扫描；设计体检。同一分支的并发运行只保留最新一次，单个 job 20 分钟超时，工作流权限只给 `contents: read` |
| 发布 | `.github/workflows/deploy-pages.yml` | 构建并上传 Pages 产物；单个 job 20 分钟超时 |
| 依赖更新 | `.github/dependabot.yml` | 每周六 09:00（Asia/Shanghai）开 PR：npm 只提 minor 与 patch（major 留给人工决定），标题前缀 `fix(deps)`，开放 PR 上限 5；GitHub Actions 依赖前缀 `chore(ci)` |

首次配置：

1. 创建公开仓库并推送代码。
2. 在仓库 Settings → Pages → Build and deployment 中，将 Source 设为 GitHub Actions。
3. 推送后访问 `https://<用户名>.github.io/naming-app/`。

免费账户只能从公开仓库发布 Pages。本项目不含密钥与个人数据。

## 适用范围与已知限制

- 应用提供的是可核对的信息：典籍出处、原句位置、字义、笔画与结构、读音与谐音、多音字、真实用名频次。不包含五行、八字、五格、生肖宜忌、吉凶或「补缺」建议。
- 卡片上的「部首」是《康熙字典》部首归属，只覆盖木、火、水、金、土五部中查得到的字（66 字；1,660 条双名中有 597 条至少一个字可标注）。未标注不代表该字没有五行属性。
- 卡片分数由本项目自定义规则计算（音韵、谐音、字频、字形、性别风格），只用于候选池内排序，不构成对名字优劣的评价。
- 界面上的带调拼音（如「松 sōng」）不是存下来的：产物里只存不带调音节与声调号，带调写法由 `src/engine/tone.ts` 按标调规则推导（有 a 标 a、`ou` 标 o、`iu` 标 u、`ui` 标 i，自成音节 m n ng ê 逐条列出）。9,629 条读音逐条与上游比对，任一条对不上就在 `src/engine/tone.test.ts` 判红；白名单成员同理由 `whitelist-L0.json` 推导。两处合计还回 20,386 B gzip。
- 名用字白名单为 310 字（种子 268 ＋ 人工过字保留 42）。扩充方式：执行 `node scripts/l0-unlock.mjs` 生成待审表（`docs/l0-待判表.md` 是同一份数据的文本形态），判定写回 `data/raw/l0-verdicts.txt`，再执行 `npm run build`；门禁会在扩表后切换为下界断言，已有候选不允许消失。0.7.0 起准入从「一级字表」放宽到「一二三级字表」——薇 琬 琰 澈 澜 笙 这类字恰恰都在二级以后，只认一级字表就永远进不来；虚词与忌讳字的闸门不变，塞进来就在构建期炸。
- 今译覆盖 1,140 句，另有 81 句出处（落在 108 条候选上）还没有译文：卡片与导出在这些位置显示「今译待补」，逐句清单在 `docs/gloss-gaps.md`，补一行即进包。验收门禁按书数覆盖率（每本不低于 60%、总体不低于 80%），不再要求"全覆盖"——但缺口必须被数出来、在界面上标出来。
- 典籍范围固定为上述七部。增加典籍需要同时更新指纹与门禁断言，规则见 `DESIGN.md`。
- 出处今译为自撰内容，无第三方校订。
