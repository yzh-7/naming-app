# 03 名字是怎么来的

这一篇讲取词口径。它决定了一个名字为什么会出现、为什么另一个不会出现，也是判断这套结果靠不靠谱的依据。口径名字在代码里叫 **Pool-B**，是"典籍原句 + 固定取字规则 + 白名单"三样凑出来的候选池。

先给结论：当前池子里有 **1,660 条双名**和 **234 个单字名**（其中 76 个单字名没有典籍出处），名用字白名单 **310 字**，出处今译进包 **1,140 句**，另有 81 句出处（落在 108 条候选上）译文待补。这些数字由 `src/data/meta.json` 记录，构建时由 `scripts/verify.mjs` 核对。

## 第一步：七部典籍

| 典籍 | 篇数 | 取词段数 | 取词段字符数 | 池内条数 |
|---|---:|---:|---:|---:|
| 诗经 | 305 | 7,260 | 29,250 | 158 |
| 楚辞 | 65 | 5,495 | 24,588 | 299 |
| 论语 | 20 | 3,682 | 15,720 | 106 |
| 水墨唐诗 | 176 | 991 | 5,832 | 157 |
| 宋词三百首 | 280 | 5,208 | 23,960 | 744 |
| 道法（22 行手工录入） | 22 行 | 68 | 321 | 39 |
| 乐府诗集 | 20 篇 | 429 | 2,134 | 22 |
| **合计** | — | **23,133** | **101,805** | **1,660** |

分句和散文用的是宽口径，卡片上会写明"宽口径取词：长短句 / 散文 / 道法，务必看原句"，数据里带 `strict: false` 标记，界面上写着"音步严格"的才是按固定节奏取词的那批。

## 第二步：把原文切成句读

原文按 `。！？；` 分句，再按 `，、：` 分句读，去标点。"句读"就是后面所有规则的工作单位：取词的两个字必须落在**同一个句读**里。跨句读的搭配不取，也不会拿别的句子凑出处。

## 第三步：第一个字落在音步起点

第一个字不是随便挑的，它要落在这一句的**音步起点**上。起点位置按体裁配（注意是"按体裁"，不是按字数——这一点是自审时改出来的）：

| 体裁 | 四言 | 五言 | 七言 | 其它字数 |
|---|---|---|---|---|
| 诗经 / 唐诗 / 乐府 | 第 1、3 字 | 第 1、3 字 | 第 1、3、5 字 | 每个位置都可作起点 |
| 楚辞 | 第 1、3 字 | 第 1、4 字（依"虚字占一步"推出来） | 第 1、3、5 字 | 每个位置都可作起点 |
| 论语 / 宋词 | 每个位置 | 每个位置 | 每个位置 | 每个位置 |

这里要讲实话：**音步规则是解释，不是事实**。词和散文没有固定节奏，所以它们的"起点 = 全取"是退化处理，不是放宽质量门槛；实现上没有单独给它们扣分，只在记录里留了 `strict: false`，界面上写"宽口径取词，务必看原句"，让你自己核对。

## 第四步：第二个字在同一句读内，隔得不太远

第二个字与第一个字在同一句读里，并且**位置间隔不超过 3**（也就是两个字中间隔 0、1 或 2 个字）。卡片上的说法是"取词段第 X 与第 Y 字（中间隔 Z 字）"，隔 1 个字以上会标"跨字取词，看原文自辨"。

按间隔统计：**间隔 1 的 803 条、间隔 2 的 506 条、间隔 3 的 351 条**（0.7.0 扩表后的现值；早期那一份池子是 727／474／324）。相邻重复字（叠字装置）保留，"假叠字"剔除。

一条名字在语料里往往不止一处可核对出处。0.14.0 起这些第二处、第三处都挂在同一条记录上：界面写着「另有 N 处出处」（518 条名字共 1,677 处，最多的是君子——除《关雎》之外另有 288 处）。这一区 0.17.0 起分页：默认只给前 12 处并写明「已显示 12／288 处」，同一区里有「再显示 12 处」「全部展开（288 处）」「只留前 12 处」三个动作（这一行里任何时刻最多两枚：默认那一页是「再显示」＋「全部展开」，全部展开之后只剩「只留前 12 处」）——翻页只是显示层，数据一处不缺，全部展开时 288 处全在（12 处以内的卡不出现这些按钮），导出 CSV 里是「其他出处数」那一列（只有处数，不塞原句正文）。**主出处的选法没变**：仍是间隔最小的那一处、同间隔取先出现的那一处，所以每条名字的 id、收藏与分享链接逐字不变（发布前用 `scripts/records-diff.mjs` 与上一版逐字段比对，1,894 条记录 0 处不一致）。

为什么要有这条：随机在整句里抓两个字，就会出"苏下彼""苏扶有"这类不通的搭配——这是某个参考项目的核心缺陷，本项目的整条口径就是为堵它而设的。

## 第五步：两道减法

1. **两个字都要在名用字白名单（L0）里。** 白名单当前 310 字：268 字种子（cnname 属性表全部用字 ∩《通用规范汉字表》一、二、三级共 8,105 字）+ 42 字人工判定保留。0.7.0 起准入从「只认一级字表」放宽到「一二三级字表」——薇 琬 琰 澈 澜 笙 这类字恰恰都在二级以后，只认一级字表就永远进不来；虚词与忌讳字的闸门不变。判定文本存在 `data/raw/l0-verdicts.txt`，它的指纹记进 `meta.L0_verdicts_sha256`，构建时核对。
2. **排除虚词、忌讳字、现代高频成词与噪声词。** 现代成词按 jieba 词频判定，词频 ≥ 5000 的直接剔除（例如"明白"）。另有一张同形风险表按"人工补录 + 频率阈值初筛"维护，因为阈值法会漏（"富强"词频 333 低于阈值，但它确实现代词），这张表是人工补录过的。

## 这两个字在典籍里挨着过吗（成词证据）

跨字取词（隔 1 个字以上）本来就是从一句里挑两个字，光靠"同句读、起点落音步"挡不住"《野有蔓草》清扬婉兮 → 清婉"这种各取一字的拼法。所以构建期为每条候选多算三个数，运行时只读不算：

| 记的是什么 | 怎么算 |
|---|---|
| 这两个字作为**相邻两字**在语料里出现的次数 | 每篇正文单独取，按句读切段（跨句读不算，逗号两侧不算一个词），段内做两字滑动窗计数 |
| 现代汉语词表里这个词的词频 | jieba 词典（已在 `data/raw` 登记、MIT 许可）收录该双字时的词频 |
| 被剪开的那个原词 | 隔字取词时，如果取词窗口里本来有一对相邻字在语料里成词，就把那一对记下来（"清婉"记的是"清扬"） |

**成词层**＝相邻出现过两次以上（262 条），或现代词表收录了这个词（362 条），或是典籍里的叠字。合计 **525 条**，这就是界面默认给你的那一档。剩下 1,135 条（其中 659 条还把原句里挨着的那对字剪开了）不是错，但它是拼出来的，所以默认不摆出来——把"只看成词的名字"点开就能看见，卡片上写着"未见成词依据"。

加分按复现次数分三档（2／10／30 次对应 +6／+9／+12）：语料一共十万字，"出现两次"说明不了它常用，分档让昊天（27 次）、明月（31 次）这类真词排到第一页去。

**名句层那 +8 分问的是另一件事：这个词被用到什么程度。**判据是跨全池的单一阈值——候选全池 1,660 条里，"这两个字在语料正文里确实挨着过"（相邻出现 ≥1 次）的那 826 条，把它们的复现次数排成一个数列，取它的 **90 分位＝4 次**；一条名字的相邻出现次数 ≥ 4 就带 `famous`，卡片"分数明细"那一行写着"原句属名句层：这个词在典籍正文里反复出现"。当前 **93／1,660 条双名、64／234 条单字名**带这一分，明月（31 次）、君子（296 次）、依依（6 次）、昊天（27 次）都在里面。旧判据不是这样：它取"每本书内取词段复现次数的 90 分位、且不低于 2"，可这七本语料里 94.6% 的取词段只出现一次，七本书的分位全是 1 或 2，`max(2, q)` 恒等于 2，那条分实际只给到 58 条，明月和君子都漏了。阈值与每一条 `famous` 现在都由 `npm run verify` 从 `data/raw` 独立重算一遍（门禁与构建脚本各写一份实现，对不上就判红），不靠产物里记的数字自证。

**有一条更彻底的路量过没走**：把语料里成词、但字不在名用字白名单内的搭配放进来，能多 6,385 对。可那些高频项是 子曰、孔子、子路、四方、小人、无人 这一类，好东西（悠悠、芳草、日月、既见）得人工逐字挑，而体积预算只装得下约 227 条双名。反过来查，两字都在白名单内、成词、却没能进池的只有 7 对——取词口径本身几乎没漏东西，缺的从来不是数量而是质量。

## 第二个来源：真实人名（0.6.0 起）

上面这条链给的是 1,660 条双名。名字数量不够，靠扩典籍太贵（每加一条双名要连带今译与字义，实测 73 B gzip），靠放开门槛又把拆词的那 1,000 多条放回来。剩下没用过的一条路是**真实姓名语料本身**：那 120 万个真名里，有很多名字两个字都在名用字白名单内，典籍里却凑不出来。

于是有了第二个来源，入选条件三条：真实语料里出现 **10～600 次**（下界滤掉只见过一两次的录入噪声——10 次意味着 120 万条真实姓名里有十个以上的人这么叫过；上界滤掉满街都是的那一档）、**两个字都在名用字白名单内**（这一档不许绕过用字口径，白名单没批过的字留给人工过字）、**不与典籍候选重名**。结果 5,096 个名字，卡片与导出里都写明"非典籍出处"，分数只吃公共部分（白名单、真实用名次数、音韵、性别），不假装有典籍出处。

史传人名（苏轼、屈原、陶潜 这类）暂时没做：七部典籍的 146 个作者名里只有"岳飞"两字都在白名单内——卡住它的还是同一件事，用字白名单。它得和过字表一起批，不为它开后门。

## 第六步：打分只用于排序

分数是若干条可解释的加减项之和，卡片上"分数明细"能逐项展开。常见的几项：

| 项 | 分值 |
|---|---:|
| 两字同在名用字表 L0（单名：单字在 L0） | +20 |
| 出处为楚辞 / 诗经 | +3 |
| 典籍叠字（依依、燕燕、昭昭） | +3 |
| 成词：这两个字在语料里相邻出现 2／10／30 次以上 | +6／＋9／＋12 |
| 成词：只有现代汉语词表收录这个词 | +2 |
| 未见成词依据 | −6 |
| 拆词：原句里相邻的那对字被剪开 | −10 |
| 原句属名句层：这个词在典籍正文里反复出现 | +8 |
| 声调有起伏 | +6 |
| 声母韵母错开，连读顺口 | +6 |
| 性别风格强匹配 / 疑似匹配 | +4 / +2 |
| 跨一字取词 | −4 |
| 名字双声（声母相同）或叠韵 | −4 |
| 三字同声调，读起来平 | −8 |
| 双唇音相邻，拗口 | −6 |
| 单字现代频度低 | −10 |
| 简拼谐音某个词 | −12 |
| 连读谐音某个词 | −20 |
| 与高频现代词同形（名字本身或姓 + 名字） | −40 |

分数**不是对名字好坏的评价**，它只在这 1,660 条内部起排序作用，而且会随你选的姓与姓氏读音变化。想按别的尺子看结果，用"排序"里的笔画少 / 用字常见度 / 按出处。

## 用字常见度是什么意思

`name_given_freq.json` 是对 114 万条真实姓名去掉姓氏首字后的用字计数（共 211 万次用字，覆盖 2,240 个字）。卡片上的档位由这个计数换算：

| 档位 | 用字次数 |
|---|---|
| 很常见 | ≥ 8000 |
| 常见 | ≥ 2000 |
| 一般 | ≥ 500 |
| 少见 | ≥ 100 |
| 冷僻 | < 100 |

这是**估算**，依据是那份姓名语料，不是户籍重名率。生成页的"用字常见度下限"筛选用的就是同一套档位。

## 部首那一行不等于五行

卡片上的"部首"讲的是"这个字的《康熙字典》部首属于哪一部"这一可核对的事实，只覆盖木、火、水、金、土五部中查得到的字（66 字；1,660 条双名里有 597 条至少一个字可以标注）。民间按偏旁定五行的做法只对这五部成立，其它部首没有可靠对应，所以一律不标注。**没标注不代表该字没有五行属性**。本应用不做五行筛选、不做八字与五格计算、不给吉凶或"补缺"建议。

## 出处今译是自己写的

`data/raw/line_gloss.tsv` 是 1,140 行"原句 ⇥ 释义"，与候选及单字名的原句逐条对应，由本项目撰写，只解释句意，不增补典故、不做命理判断，也不引用古诗文网或任何整理本的注释与译文。门禁核对"唯一原句数等于释义条数"，缺一条、多一条、原句重复都会在构建期失败。这些今译没有第三方校订。

## 每条候选的编号长什么样

编号形如 `Bsj_caiwei_yiyi_001`：层级（B）+ 典籍代号（sj = 诗经）+ 篇名 + 名字去声调拼音 + 序号。序号按"篇 + 去声调拼音"这个前缀计数，所以池子扩容时旧编号不会位移——收藏与拉黑按完整编号存，扩容后你的收藏仍然指得回原来那条。

同篇同音不同字会共用前缀：当前 1,660 条双名共有 1,659 个前缀，其中 1 组 2 条（《诗经·采薇》的"依依"与"翼翼"拼音都是 `yiyi`，编号 `_001` 与 `_002`）。完整编号仍然唯一，界面、收藏、拉黑都按完整编号取条目。这条统计不是缺陷，它作为事实写进 `meta.id_prefix_stats` 并由门禁独立重算对账，语料扩充后组数与最大组的变化会在门禁上暴露。

## 有一条放宽路线算过但没发布

把白名单放宽到全部规范汉字后，可取的搭配数量是 51,959 条（`meta.pool_C`），混合口径实测 16,015 条。这些数字只是**池内计数**，没有打进发布产物：随包体积的天花板先撞线的是站点产物那条预算（见 [06 命令、门禁与部署](06-命令、门禁与部署.md)），而且字级 L1/L2 与"扩大范围"开关需要同一套规则先产出可用的池子。

## 池子是怎么从 463 长到 1,660 的

知道这段变化有助于理解结果为什么长这样：

| 阶段 | 白名单 | 双名条数 | 说明 |
|---|---|---:|---|
| 只取相邻两字（调研阶段） | 199 字（cnname ∩ 一级字表） | 202 | 早期口径 |
| 间隔放宽到 ≤3 | 199 字种子 | 463 | 早期以单文件形态分发的那份产物就是这一份池子 |
| 扩表 + 并入乐府 | 293 字（268 种子 + 25 人工保留）、七部典籍 | 1,525 | 0.4.0–0.6.0 |
| 再扩表（准入放宽到二三级字表） | 310 字（268 种子 + 42 人工保留） | 1,660 | 当前状态 |

那 463 条今天**全部还在**池子里（编号逐条比对：463 条全在新池中），新增的 1,062 条来自白名单扩表和乐府并入。规模从来不是瓶颈，逐字判定才是——人工过字挑进来的字，直接决定挑进来的名字是什么口味。
