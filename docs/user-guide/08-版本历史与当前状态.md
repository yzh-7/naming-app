## 各版对用户来说变了什么

### 0.1.0（2026-10-16 起，至 10-26）

首版上线的内容就是今天的主干（名字数量已从 1,525 条涨到 1,660 条，其余框架未变）：七部典籍、1,140 行今译；生成、自选、收藏与分组、拉黑、典籍开关、篇名与指定用字筛选、分享链接与二维码、JSON 导入导出、CSV 导出、深浅三档主题；manifest + Service Worker 离线；GitHub Pages 发布。

这一版里也有一段开发期值得知道：自选页 2026-10-19 才加（一度拆成独立的 `compose.html`，10-20 又回到单入口 hash 路由）；今译 2026-10-19 接入；第七部典籍"乐府"2026-10-24 并入；全站视觉与排版重做、深浅三档落地、手机端按手指尺寸也是 10-24 那一次。

### 0.2.0（2026-10-26）

- 卡片上直接给出**篇名筛选**与**同音写法**入口；页面加载失败时有兜底页。
- 收藏分组可改名、可解散（解散只删组名，组里的收藏退回未分组）；对不上组的收藏单独列出。
- 收藏导出 CSV 增加"分组""备注"两列。
- 分享链接新增 `gw` 参数（含"疑似"那一档）。
- 页脚开始显示**应用版本与语料指纹**。
- 修复：篇名筛选改精确匹配（原先按包含匹配，会把邻近篇名带进来）；导入失败分成三种说法（不是 JSON / 不是本应用导出的 / 是空的）；二维码画不出来时返回可判定的结果；自选页同一个字填进两格时列表键不再重复。
- 输入口径统一：本机存储、导入文件、分享链接三条路径共用一份收敛规则，不可信取值回该项默认。
- 门禁：单文件产物的体积判定接进 CI（第一次接就被压缩实现的差值撞挂，于是单文件预算单列 450 KiB）；Service Worker 缓存名不再写死；版本号注入三个出口。

### 0.3.0（2026-10-27）

- **新增"禁用字"（避讳字）筛选**：名里出现其中任意一个字的候选整条不出现，只查名不查姓，最多 8 个字。它同时进入本机存储、导入文件、分享链接（`ac` 参数）、候选导出、名单图与分页计数。自选页不受它筛除，但挑到时会明说。
- 结果为 0 时的定位提示补齐（指定字 / 禁用字各自给"点不限"的入口）。
- 一批实用修复：CSV 防 Excel/WPS 执行公式（`=` `+` `-` `@` 打头前置前导单引号）；导入文件 8 MiB 上限（选文件时先拒、读出来后再按实际字节判一次）；离线时资源请求不再退回页面（改回 504 纯文本，避免"脚本语法错误"这种看不懂的表现）；生僻汉字不再被静默丢掉（改按 Unicode 汉字属性判）；逐字输入不再把前面打的字顶掉；"同篇还有 N 条"改按当前筛选计数；收藏页说明禁用字不参与筛选。
- 门禁：CI 加并发与 20 分钟超时、权限收成 `contents: read`；`npm audit --audit-level=high` 进 CI；新增 dependabot 每周六 09:00 提 minor/patch PR；`tsconfig.json` 补入 `tests/` 与两个配置文件。

### 0.3.1（2026-10-27）

**没有用户可见变化。** 收口的是三件事：补上仓库根的 MIT `LICENSE`（范围是本仓库自撰代码与文档，上游语料与第三方库不被重新授权）；44 个文件统一成 prettier 形态并把 `format:check` 接成 `build` 的第一环；打开 `noUncheckedIndexedAccess`，122 处下标取值逐处改成先确认再取值（不新增 `!`、`as`、`@ts-ignore`）。体积代价：单文件产物 gzip +174 B（格式统一 13 B，判空分支本身 161 B）。

### 0.3.1 之后（未发版，已随 main 部署）

只动测试、门禁配置与文档：新增 `tests/gates/` 12 条（把 `verify` 与 `size-check` 这两条门禁自身的失败路径测了）、新增 `ErrorBoundary` 4 条用例、接上 vitest 覆盖率口径与阈值并上调一档、补 `pwa.ts` / `Compose.tsx` / `NameCard.tsx` / `App.tsx` 的覆盖盲区、做一轮变异抽查揪出六处不会红的断言。用例数 183 → 252，产物逐字节未变，所以不升版本号。

## 读版本历史时有两条 Actions 侧事实

1. **一次推送只按 head 建 run。** 一批推上去的中间提交不单独产生 run，所以不是每版"最后一次提交"都查得到属于它的那条门禁记录。要看现行 head 的结论，取 Actions 列表里最上头那一对。
2. **索引表里挂着两条红的 CI run，都不是那一版的门禁跑红。** 一条是 `ci.yml` 把 `timeout-minutes` 写在 workflow 顶层导致整份文件被判非法（两分钟后的 `81f2bc8` 修好），一条是初始推送时 CI 自身没绿过。三个后补标签一起推时，只有指向那份非法文件的 `v0.3.0` 生成了 run——合法的工作流文件在标签推送上不触发（`on: push` 只列了 `branches`）。

完整条目在仓库 `CHANGELOG.md`。要看某一次改动为什么这么做，那里面比这套文档更细。
