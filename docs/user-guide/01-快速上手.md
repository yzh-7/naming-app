# 01 快速上手

先说结论：**要取名不用装任何东西**。打开 <https://yzh-7.github.io/naming-app/#/> 就能用。下面四种用法按"省事程度"排序，按你的场景挑一种。

| 用法 | 需要准备 | 适合 |
|---|---|---|
| 在线直接用 | 一个现代浏览器 | 绝大多数人 |
| 装到手机上（PWA） | 一次联网 | 想把它当 App 用、常在外头取名 |
| 单文件版双击打开 | 一个 1.6 MB 的 HTML 文件 | 要完全离线、要发给长辈、要存档 |
| 本地跑源码 | Node 22.19 或更高 | 要改代码、要自己构建 |

## 用法一：在线直接用

地址：<https://yzh-7.github.io/naming-app/#/>

页面顶部有四个页签：**生成**、**自选**、**收藏**、**拉黑**。第一次用只要走这四步：

1. 在"姓"那一格里输入姓氏。复姓可以直接打（最多两个字），姓的首字是多音字时上方会多出一个读音下拉框，选一个——读音会影响所有名字的读音核对和排序。
2. 想收窄就先设一两个筛选：名字字数（双名 / 单名）、性别风格（不限 / 偏男 / 偏女，旁边有个"含疑似"开关）、典籍开关。其余的收在"高级筛选"里，默认收起。
3. 看卡片。每张卡片给的是：名字、读音、性别倾向、出处（典籍 + 篇名 + 原句 + 今译）、字义、笔画与结构、每个字在真实姓名里的常见度，有提醒事项时才出现警示行。
4. 挑顺眼的点"收藏"。想翻下一页点"换一批"，想一屏看全把"每批条数"选成"全部 N 条"。

生成页顶部那行说明写着取词口径："名字的起点落在典籍原句的音步边界上，第二个字取同句读内隔 0～3 字的位置，两字都须在名用字表内。"这句是整个应用的凭据，想知道它到底怎么执行，读 [03 名字是怎么来的](03-名字是怎么来的.md)。

## 用法二：装到手机上

这是个 PWA，可以装成手机上的独立应用：

- **Android（Chrome / Edge）**：打开站点，菜单里选"添加到主屏幕"或"安装应用"。
- **iPhone / iPad（Safari）**：分享按钮 → "添加到主屏幕"。
- **电脑（Chrome / Edge）**：地址栏右侧的安装图标，或菜单里的"安装 …"。

装好之后图标叫"取名"，打开时没有浏览器地址栏。首次安装需要联网一次，之后**断网也能打开**——语料和界面都在本机缓存里，筛选与计算全在浏览器内完成。断网时页面顶部会写"离线模式：数据都来自本机缓存，功能正常"。

离线机制的细则（缓存名怎么算、为什么刷新即取新版）在 [07 离线与安卓分发](07-离线与安卓分发.md)。

## 用法三：单文件版

整个应用可以打成一个 HTML 文件，双击就开，不需要网络也不需要服务器：

```bash
$ npm run build:single
```

产物是 `dist-single/index.html`，当前 1,678,890 B（1.60 MiB），gzip 后 414,892 B。仓库把它打进 CI 做体积核对，但**不发布**它——线上发布用的是分包的 `dist/`。

拿到这个文件后直接双击打开即可。在 `file://` 下不会注册 Service Worker，也就不会去抢浏览器缓存。适合"发给长辈""存档一份""塞进 U 盘"这类场景。

这个形态有个早期版本曾以 `取名.html` 的名字单独分发过（463 条候选、六部典籍，没有今天的自选页、今译、分组、禁用字与深浅主题）。**别拿旧副本当成品用**，要离线版就按上面的命令自己构建。

## 用法四：本地跑源码

```bash
$ node -v          # 需要 22.19 或更高（CI 覆盖 22 与 24）
$ npm install
$ npm run dev      # 先生成数据，再启动 Vite 开发服务器
$ npm run test:e2e # 端到端测试需要 Chromium，首次先执行 npx playwright install chromium
```

`npm run dev` 会先执行 `npm run build:data`，把 `data/raw/` 里的语料固化成 `src/data/*.json`，再起开发服务器。构建产物在 `dist/`，本地预览可以 `npx vite preview`，或者用仓库自带的一条：

```bash
$ npm run serve    # 用 python3 -m http.server 静态伺服 dist/，端口 5178
```

完整的命令表和每条命令干什么，见 [06 命令、门禁与部署](06-命令、门禁与部署.md)。

## 你的数据存在哪里

收藏、拉黑、姓氏、筛选设置、自选页草稿、主题选择都存在**你这台设备的浏览器 `localStorage`** 里，不落服务器，也不上传：

| 键 | 存的东西 |
|---|---|
| `naming.favorites.v1` | 收藏记录（编号、备注、分组、收藏时间） |
| `naming.blocklist.v1` | 拉黑名单 |
| `naming.surname.v1` / `naming.surnameReading.v1` | 姓氏与姓氏读音序号 |
| `naming.opts.v1` | 筛选设置 |
| `naming.theme.v1` | 主题：`system` / `light` / `dark` |
| `naming.compose.v1` | 自选页草稿 |

由此推出三件实用的事：

1. **换设备不会自动同步。** 换手机、换浏览器、用隐私模式，收藏都带不过去。想带走就用"导出"存成 JSON，在新设备上"导入"，选合并或覆盖。
2. **浏览器清空站点数据 = 收藏没了。** 长期用建议定期导出一份 JSON 备份。
3. **分享链接只带筛选条件**，不含收藏与拉黑。把链接发给别人是安全的，但别人打不开你的收藏。

## 隐私方面的一句话

页面运行时不发网络请求，没有广告、没有统计脚本、没有账号体系，也不碰五行、八字、五格、生肖宜忌。你能在卡片上看到的所有信息——出处、读音、笔画、结构、用字常见度——都是可核对的事实。
