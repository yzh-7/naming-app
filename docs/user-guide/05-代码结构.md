# 05 代码结构

这一篇是给要改代码的人看的地图。读完你应该知道：一个名字从哪个函数出来、界面上一句文案在哪个文件、改一个筛选条件要动哪几处。

技术栈只有三样自己选的：React 19 + TypeScript 5.9 + Vite 8，样式是 Tailwind 4 的 CSS-first 写法。运行时依赖只有一个 `uqr`（二维码），其余都在构建期。

## 目录地图

```
data/raw/          上游语料、字表、派生输入、SHA256SUMS、许可全文
scripts/           构建管线、门禁、设计期诊断
  build-data.mjs     data/raw → src/data/*.json（唯一的数据来源）
  verify.mjs         数据门禁
  size-check.mjs     体积门禁
  design-audit.mjs   设计体检（40 组视口 × 主题 × 页面）
  screenshots.mjs    文档截图
  derive-dict.mjs    一次性派生三份精简输入
  l0-unlock.mjs / l0-keep.mjs  白名单扩表与共用口径
  measure-*.mjs      设计期实测（漏斗、白名单曲线、间隔阶梯）
src/
  engine/          纯函数：数据装配与运行时自检、取词、打分、音韵、字形、常见度
    data.ts          加载 src/data/*.json，逐份做结构自检（asPool / asChars / asMeta）
    name.ts          universe / plan / scoreItem / composeName / charFacts …
    types.ts         Opts 与各档位常量、汉字与输入清洗（isHan / cleanSurname / cleanAvoid）
  store/           持久化与传输
    local.ts         localStorage 读写 + 唯一的输入收敛规则（sanitizeOpts / sanitizeReading）
    transfer.ts      导出文件的构造与解析、URL 参数读写
  ui/              Controls、NameCard、Compose、TopNav、ThemeControl、ErrorBoundary
  lib/             share.ts（分享卡与名单长图）、candidates.ts（候选全量导出）、pwa.ts（Service Worker）
  data/            构建产物，勿手改
  App.tsx          四个页签、导入导出、复制链接、页头与主题、离线与新版本提示、打印、URL 初始状态
  main.tsx         挂载与 Service Worker 注册
public/            manifest、图标、sw.js
tests/e2e/         Playwright 端到端与 axe 扫描
tests/gates/       两条门禁脚本自身的失败路径用例
docs/screenshots/  文档截图
```

一句话总结分层：`engine` 不认识界面，`store` 不认识候选，`ui` 只调这两层。对比表 `Compare` 是个例外，它定义在 `App.tsx` 里。

## 一次生成走了哪些函数

用户在生成页点一下"换一批"，走的是这条链：

```
App.tsx  batch + 1
  └─ plan(surname, opts, batch, surReading)            engine/name.ts
       ├─ universe(opts)                               按顺序收窄候选集合
       │    ├─ bookUniverse      字数（双名池 / 单名池）、典籍开关、只看叠字
       │    ├─ genderPass        性别风格；中性名保留，反向名排除，"疑似"看开关
       │    ├─ passesShape       事实类筛选：整名笔画上限、用字常见度下限、避开同结构
       │    ├─ mustPass          指定用字与位置
       │    ├─ avoidPass         禁用字（只查名不查姓）
       │    ├─ 篇名精确匹配       opts.title 为空则不限
       │    └─ 搜索              searchText(名字 + 拼音 + 篇名 + 作者) 包含匹配
       ├─ 去掉 opts.exclude（拉黑名单）
       ├─ 顺手算 titleCounts      卡片上"同篇还有 N 条"就是这个数，与池子同一集合
       ├─ scoreItem(...)          每条打分，返回 deltas 明细
       ├─ 按 opts.sort 排序
       ├─ paginate + batch 取模   分页不重复、不漏项
       └─ 排序是按分数/按出处时，页内再按典籍错开，避免一屏全是同一本书
```

自选页不走这条路：`composeName` 只做读音、谐音、字形核对，不套候选池分数；出处用 `findCombo` 精确查 Pool-B 与单字池，查不到就显示"未见此搭配"；"同句读搭配字"用 `pairCandidates` 现算。

## 输入收敛只有一份规则

不可信输入有三条来源：本机 `localStorage`、导入的 JSON 文件、分享链接的查询参数。三条路径**共用同一份**清洗规则，写在 `store/local.ts`（`sanitizeOpts`、`sanitizeReading`）和 `engine/types.ts`（`cleanSurname`、`cleanAvoid`、`isHan`）。`transfer.ts` 里不再自带一份副本——以前有两份，改一处漏一处。

收敛的口径是"不可信就回该项默认"，**不夹到边界，也不静默丢弃这一项**。例如 `?n=601` 回默认 12 条，`?sm=999` 回 0（不限）。"是不是汉字"按 Unicode 的 `\p{Script=Han}` 判，扩展 A 区（㐀）、兼容区（豈）与扩展 B 以后的字不会被静默删掉——以前写 `[一-鿿]`，用户打进去了看不见、筛选也不生效，看着像"设了但没用"。

几条容易踩的点：

- 姓的清洗只发生在失焦与提交时。实时裁剪输入框会打断拼音输入法（`yuan` 还没上屏就被截成 `yu`）。
- "指定用字""禁用字"两个框共用 `Controls.tsx` 里的 `CharField`：打字期间 DOM 归用户，只有外部改变（点"不限"、导入、带参数的链接）和失焦时才把 DOM 拉回归一化后的值，框正被 focused 时不写。以前用 `key` 重建输入框，打第二个字的瞬间框被换成带着旧值的新一份，后打的字被顶掉——只有真键盘路径能复现，用 `fill()` 灌值的测试测不出来。

## localStorage 键

| 键 | 内容 |
|---|---|
| `naming.favorites.v1` | 收藏记录 `{ id, note?, group?, ts }`，会从旧版 `string[]` 自动升级 |
| `naming.blocklist.v1` | 拉黑名单 |
| `naming.surname.v1` / `naming.surnameReading.v1` | 姓氏与姓氏读音序号 |
| `naming.opts.v1` | 筛选配置，`loadOpts` 兼容历史字段 |
| `naming.theme.v1` | `system` / `light` / `dark`，标记加在 `<html>` 上 |
| `naming.compose.v1` | 自选页草稿 |

## 链接参数

链接只编码筛选条件，不含收藏与拉黑。`fromQuery` 是部分合并：参数出现了这一项才进入状态（越界即默认值），没出现的沿用本机已存偏好；`toQuery` 不写默认值。

| 参数 | 含义 | 参数 | 含义 |
|---|---|---|---|
| `s` | 姓氏 | `o` | 排序（score / strokes / popular / book） |
| `r` | 姓氏读音序号 | `sm` | 整名笔画上限 |
| `g` | 性别风格（f / m） | `nm` | 避开两字同结构 |
| `gw` | 含"疑似"一档，只在 `g` 存在时写出 | `pf` | 用字常见度下限 |
| `len` | 字数，`1` 表示只看单名 | `b` | 典籍开关，7 位 0/1 串（诗经、楚辞、论语、唐诗、宋词、道法、乐府） |
| `n` | 每批条数，`all` 表示不限 | `d` | 只看叠字 |
| `q` | 搜索词 | `mc` / `mp` | 指定用字与其位置（first / last） |
| `t` | 篇名（只看这一篇） | `ac` | 禁用字，1–8 个汉字，不限时不写出 |

## 样式令牌

`src/styles.css` 用 Tailwind 4 的 `@theme` 定义刻度、`@utility` 定义可复用的组件类。**深色主题不使用 `dark:` 前缀**，而是由 `.dark` 覆盖同名 CSS 变量，组件只引用语义化令牌（`--canvas`、`--surface`、`--ink`、`--accent`、`--cool-*` 偏男、`--warm-*` 偏女、`--warn` / `--danger` / `--ok`）。改配色只改这一处，不需要逐组件加 `dark:`。

断点：`xs` 384（自定义，表单转两列）、`sm` 640（侧栏与一行布局、页头收成一行）、`lg` 1024、`xl` 1280。44 px 触控尺寸保持到宽度 1023 px，紧凑档 36 px 只在 `lg` 生效。可访问性约定：可见文字必须属于可访问名的一部分，`aria-label` 只用于图标按钮与分组；状态按钮用 `aria-pressed`；折叠区用 `details` / `summary`；装饰字符标 `aria-hidden`。

## 两个命名陷阱

- `NameCard.tsx` 里的局部变量 `shadow` 表示阴影，**不要改名成 `shape`**，会和 `shapeTags`（笔画与结构标签）撞名。
- 要加"几本典籍"这种计数，用 `types.ts` 里的 `BOOK_COUNT`，别在文案里手写数字，否则加书时必漏改。
