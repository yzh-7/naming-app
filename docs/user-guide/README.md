# 取名 · 典籍取词 —— 文档目录

在线版：<https://yzh-7.github.io/naming-app/#/>
代码仓库：<https://github.com/yzh-7/naming-app>

一句话说明白这个项目：从七部典籍的原句里取词、组成名字，每个名字都给得出处原句、读音、字义、笔画、用字常见度。数据在构建时打包进页面，页面打开以后不再发出任何网络请求，也没有广告、统计和命理判断。

这套文档是面向使用者的中文说明，写于 2026-10-30，逐条对着仓库 `main` 分支的 `6e86b68`（2026-10-27）核对；线上跑的是 0.3.1，页脚显示「应用版本 0.3.1 · 语料指纹 b30924ef5d04」。**它与仓库根目录的四份文档有分工**：那四份是权威口径（本文与其不一致时以它们为准），这一套讲得更直白、更按"你要做什么"来组织。

## 先看哪一篇

| 你是这种情况 | 建议按这个顺序读 |
|---|---|
| 只想给孩子取个名字，不想碰代码 | 01 快速上手 → 02 使用手册 → 10 常见问题 |
| 想知道这些名字到底是怎么挑出来的、靠不靠谱 | 03 名字是怎么来的 → 04 数据与语料 |
| 准备改代码或者接手维护 | 05 代码结构 → 06 命令、门禁与部署 → 08 版本历史与当前状态 |
| 想让它离线用，或者打包成安卓应用 | 07 离线与安卓分发 |

赶时间的话，只读 01 和 02 就够用了，其余的等你有疑问再翻。

## 两条贯穿全部文档的口径

1. **只给可核对的事实。** 出处、原句位置、读音、笔画、结构、真实姓名里的用字频次——这些都能查。五行、八字、五格、生肖宜忌、吉凶、"补缺"一概不做，卡片上的分数也只管候选池内的排序，不是对名字好坏的评价。
2. **数字都带出处。** 文档里出现的候选条数、字数、体积、用例数，都是从仓库当前状态抄下来的，并注明取自哪个文件。数字变了通常意味着语料或代码变了，这时应该先重跑 `npm run build` 再看文档。
